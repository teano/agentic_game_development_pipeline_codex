# QA semantic artifact

Follow `assignment.artifact_schema` and the shared [QA acceptance contract](../../gamedev-pipeline/references/qa-acceptance-contract.md). `context.qa_contract.definition`, resolved through the generated assignment reader, is the same source-bound assertion/method inventory delivered to Engineer and Review. Read shared method definitions once and keep their operative permission/exception text. Use its approved alternatives and evidence types; do not independently strengthen the method or substitute a weaker observation.

For a bound contract, return one `{id,outcome,evidence,assertions}` result per `context.required_identity_ids` and one result for every declared assertion, on pass, fail and blocked. Identity-level `checks[].evidence` is a non-empty **string**, including fail/not_run identities: state the actual evidence or the concrete unexecuted boundary. It is distinct from `checks[].assertions[].evidence`, an **array** of exact `{type,ref,observation}` records whose required types and permitted emptiness follow the assertion outcome and shared contract. Do not substitute one level's shape for the other. The shared contract defines assertion fields, applicability, dependencies and concrete `not_run` reasons. Complete independent available work before returning; an unavailable capability does not excuse unrelated scenarios. Prior observations in `context.qa_previous_observations` identify work and gaps but grant no credit. Revalidate environment and method before relying on them.

When `context.qa_contract.status` is `unresolved`, retain available observations and return `blocked` with the precise missing source-grounded contract and required binding action; `checks: []` is permitted at this boundary. Do not invent method equivalence, reinterpret approved acceptance, regenerate approved documents or claim PASS. The authorized owner can bind the contract through `init --qa-contract` at an idle boundary; current-candidate Review then assesses it independently.

Before constructing results, apply [Independent assessment before serialization](../../gamedev-pipeline/references/qa-acceptance-contract.md#independent-assessment-before-serialization). Serializers format actual assessed facts only. Shared observations need independent ID-to-proof mapping; capability lists, AUTO prefixes, green receipts and generated test-name claims grant no pass. Exact common construction references must materialize into this unchanged canonical shape.

An inspected missing mandatory proof/case across all approved alternatives uses the shared contract's `not_run` / `verification_incomplete` route with exact gap evidence, not a fictional executed failure or missing authority. Its identity and QA aggregate fail through existing Engineering remediation. Actual unavailable assertions remain present and unverified. A conditional scenario with proved false applicability uses `not_applicable`; an always-applicable conditional-policy/reachability check may pass through its approved composed proof.

Machine evidence/check execution follows [Active checks](../../gamedev-pipeline/references/execution-contract.md#check-inside-active-engineering-or-qa); behavior and applicability proof follows [Evidence sufficiency](../../gamedev-pipeline/references/interaction-evidence.md#evidence-sufficiency). Verdict-changing ambiguity uses the existing nonterminal clarification route, never questions attached to pass. Relevant technical entries and actual obstacles follow the [event-specific instruction route](../../gamedev-pipeline/references/stage-handoff-invariant.md#event-specific-instruction-route); journal text grants no acceptance credit.

The controller checks the complete declared inventory, methods, evidence shape and bindings. It does not establish the truth of observations or that a human-readable source was decomposed correctly. Independent QA owns that assessment. Do not put Git tree OIDs, command digests, process results or controller state in the worker artifact. The issued assignment authorizes its exact terminal output path.
