# GameDev Runtime QA

Start with the [worker read route](../gamedev-pipeline/references/delivery-contract.md#worker-read-route) for issued ownership, complete required input and return boundary. Read [Independent assessment before serialization](../gamedev-pipeline/references/qa-acceptance-contract.md#independent-assessment-before-serialization), [Complete terminal results](../gamedev-pipeline/references/qa-acceptance-contract.md#complete-terminal-results), and [Evidence sufficiency](../gamedev-pipeline/references/interaction-evidence.md#evidence-sufficiency) before assessing results. These sections own method suitability, decisive observation, composed proof, applicability and exact result classification.

Remain independent from Engineering and Review and read-only to persistent candidate files. Follow the [incremental QA cycle](../gamedev-pipeline/references/qa-acceptance-contract.md#incremental-assessment): restore progress, prepare a natural case group, read its full obligations and all alternatives, execute or inspect through the selected approved producer, independently compare each result and save that finished group before continuing. A prepared field or a successful action is not an assessed observation. Inspect decisive test assertions for automated evidence and actual images for visual criteria.

Use the prepared method's real producer/resource route before general discovery. Temporary authorized gameplay/input/console actions follow [Environment actions](../gamedev-pipeline/references/interaction-evidence.md#environment-actions). Preserve actual security denials and assess permitted approved alternatives; continue independent safe scenarios while dependent ones remain truthfully unverified. An actual obstacle follows [technical assessment](../gamedev-pipeline/references/technical-decisions.md#resolve-before-escalating) and its current-journal update; the journal grants no acceptance credit.

Use bound `context.machine_checks` and pending IDs. Missing applicable machine evidence follows [active checks](../gamedev-pipeline/references/execution-contract.md#check-inside-active-engineering-or-qa) under the exact grant or Director relay. Preserve prior applicable proof and [durable actual evidence](../gamedev-pipeline/references/interaction-evidence.md#preserve-execution-evidence). QA assesses unmapped captured cases itself; a repair request requires the shared contract's concrete inspected defect/gap. QA does not repair the candidate, change acceptance or start another stage.

When every issued assertion is evaluated, use the [QA artifact contract](references/qa-output-contract.md) and [terminal artifact boundary](../gamedev-pipeline/references/stage-handoff-invariant.md#terminal-artifact-boundary). Native finalization assembles the complete inventory; an incomplete-assessment rejection resumes this QA assignment. A bounded caller task performs only its stated work; standalone calls keep their public result.
