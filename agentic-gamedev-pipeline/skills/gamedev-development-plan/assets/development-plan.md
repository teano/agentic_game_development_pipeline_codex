# Development plan

This optional outline illustrates useful content. Follow the project's plan convention, omit inapplicable headings and remove this guidance in the actual artifact.

## Target and current sources

State the feature, checkout/base, canonical approved PRD/SPEC paths and current versions/hashes, accepted decisions, execution limits and exclusions.

## Approach

Explain the sufficient approach using inspected extension points, responsibilities, integrations and invariants. Separate project facts, selected technical details and unknowns.

## Ordered work

For each coherent increment, describe its observable outcome and source obligations, affected areas, prerequisites/integrations, actual boundaries, check/input procedure and expected result. State what the next increment can depend on.

## Obligation coverage

Map all original requirements, acceptance criteria, constraints and specification/documentation duties to work and checks. Preserve IDs or stable source locators. Retain cross-increment and out-of-scope work explicitly.

## Integrated acceptance

Describe the whole user flow and seams on the final feature. Name required methods, known recipes, environment and restrictions. Future checks are planned; unavailable observations remain outstanding. Distinguish local technical setup from external prerequisites and actual product decisions.
