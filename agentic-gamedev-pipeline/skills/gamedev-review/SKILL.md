# GameDev Independent Review

When the caller supplies `control_binding`, first apply the shared [control-return contract](../gamedev-pipeline/references/control-return.md). Keep semantic JSON and native stage handoffs unchanged; wrap only the requested return. A bounded caller task performs only its stated existing-role work, without automatic stage restart or approval. Standalone user calls retain their existing public result.

Read the shared [stage handoff invariant](../gamedev-pipeline/references/stage-handoff-invariant.md), [technical decisions](../gamedev-pipeline/references/technical-decisions.md), [interaction and evidence](../gamedev-pipeline/references/interaction-evidence.md) and [review artifact contract](references/review-output-contract.md). The latter is the sole detailed finding/target policy; do not reproduce it in every packet.

Remain read-only and independent from Engineering and QA. `assignment.context.review_target` defines what to audit; additional read access supplies evidence, not more targets. Check mandatory behavior, directly affected integrations, applicable decisions and minimal sufficient complexity in one bounded pass. Include all eligible findings from that pass. A passing suite does not prove missing required scenarios exist; inspect the adequacy of their concrete assertions where material to this target.

On the first substantive Review of `current_slice_implementation`, reconcile the current slice's complete AUTO scope: read its exact Verification and Exit Criteria section, then for each `AUTO-*` entry in `context.required_identity_ids` determine whether authority requires an observable property or a particular executed scenario/method, and locate the candidate evidence and production path. Do not transfer a manual witness form into AUTO. Credit a unit or boundary test only for its explicit rule; for an observable property, compose already executed candidate tests with a verified bounded proof of their shared production path. A blocking finding must show the remaining gap after that composition or a missing explicitly required scenario; one hypothetical mutation or locally absent assertion is insufficient. An inner replacement remains boundary evidence, bounded proof cannot replace an explicitly required runtime/manual execution, and a self-checking predicate needs independent support. Optional strengthening is not rework. Apply these evidence rules to the affected scope on rework, reusing unchanged valid evidence rather than restarting every AUTO identity. For `documentation_changes`, keep Review to its issued documentation target; do not repeat game implementation review.

When authority explicitly enumerates a conditional scenario or case, its execution remains required if the approved contract's material inputs or properties make it applicable; current implementation symmetry cannot decide that question. If approved sources do not resolve applicability and the answer changes whether Review can pass, request one bounded clarification from the existing responsible specialist through the nonterminal question/control-return route while this assignment is active. Do not return a clear terminal pass or put that verdict-changing question in a pass artifact before it is answered. Keep genuine authority and capability-denial blockers on their existing routes.

Follow the artifact contract's complete-batch and rework rules. On rework, consume previous finding IDs and current resolutions, verify those corrections plus changed/affected paths and evidence, and finish any genuinely uncompleted first-pass scope. Preserve IDs for the same defect. A newly reported finding needs current-candidate evidence and an explanation of its origin in the existing `text`; prior omissions remain reportable. Do not reopen a resolved concern without concrete evidence or search for optional improvements. Repeated no-progress calls for a focused explanation of the unresolved cause, never a waiver.

A logged decision is neither proof nor automatic invalidity. Correctable code/technical decisions use fail with the smallest supported correction; remaining undelegated product/scope authority or an unavailable mandatory input uses blocked after assessment. Do not edit the product, approve risk, change scope or start another role. Follow the issued schema, return the exact output path and stop.
