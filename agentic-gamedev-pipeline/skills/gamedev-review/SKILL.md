# GameDev Independent Review

## Working procedure

Remain independent from Engineering and QA and read-only to the product. Follow this order for the issued Review target; a bounded caller task performs only its stated work and standalone calls keep their public result.

1. **Read the current assignment and target.** Run the [worker read route](../gamedev-pipeline/references/delivery-contract.md#worker-read-route) and consume the issued ownership, complete required input and return boundary. A requested [bounded unchanged-failure answer](#bounded-unchanged-failure-answer) follows that caller route instead of a native verdict. `context.review_target` defines the native Review target; read access does not enlarge it. Read the [Review artifact contract](references/review-output-contract.md) for finding eligibility, condition decomposition and verdict rules. For an initial Review, continue with the whole assigned target in step 2. For rework, consume [Repair input](../gamedev-pipeline/references/delivery-contract.md#repair-input) and verify the latest rejection against the claimed correction. This same Review owner reassesses every current required condition, including resolved rows, plus changed/affected integrations and genuinely unfinished first-pass scope; unchanged valid proof remains usable.
2. **Establish the mandatory result.** For product work, read the target's source-bound QA obligations and approved methods and compare their extraction with the cited approved sources. Establish applicable premises, variants and decisive expected observations independently of Engineering's claim. For `documentation_changes`, inspect only the issued documentation target. A verdict-changing source/applicability ambiguity takes the existing nonterminal clarification route before judgment, then returns here with the answer. Current technical journal text grants neither validity nor acceptance.
3. **Inspect the target and its actual proof.** Finish the entire available first-pass target even after finding a defect. For the issued product target, [compare mandatory automated observations with the actual coupled test assertions](../gamedev-pipeline/references/interaction-evidence.md#compare-automated-acceptance-with-test-assertions): inspect test bodies, material premises at action time, production paths and decisive assertions, then join them to existing `context.machine_checks` and durable execution records. An empty `assignment.checks` does not erase supplied evidence. Seek a missing exact locator through its existing owner before requesting new execution; Review never executes controller-owned argv. Apply [Evidence sufficiency](../gamedev-pipeline/references/interaction-evidence.md#evidence-sufficiency) to the whole available proof, including sufficient composition/source invariants and genuine applicability. Do not demand impossible execution, optional strengthening, repetition of valid checks or a preferred implementation. On rework, perform this inspection for the scope established in step 1; Engineering's `addressed` never supplies independent resolution. For a QA-origin repair, inspect the exact attempted method, bound observed gap and concrete repair target; unfinished QA mapping alone establishes no product defect or new Engineering obligation.
4. **Resolve conditions and batch findings.** Independently compare the inspected result with every applicable mandatory obligation in scope. For rework, produce the contract's complete `finding_resolutions` map, preserving original IDs and meaning; reuse unaffected valid proof rather than repeating the full target or suite. Check all proposed new findings against authority and complementary proof, consolidate duplicate symptoms and remove unsupported or optional demands. Return every remaining eligible current finding in one batch under the artifact contract. A demonstrated defect with an authority-preserving correction is fail. Finish independent available scope before classifying a genuinely unavailable mandatory prerequisite or undelegated decision as blocked through [technical assessment](../gamedev-pipeline/references/technical-decisions.md#resolve-before-escalating); a limited tool denial leaves unrelated permitted inspection available. Unassessed blocked scope stays explicit.
5. **Publish the assigned result and stop.** For native Review, write the exact issued schema-bound result under the [terminal artifact boundary](../gamedev-pipeline/references/stage-handoff-invariant.md#terminal-artifact-boundary). Pass requires the artifact contract's empty findings and complete independently resolved condition map, and completes only this assigned Review. It grants no final QA, product edits, risk acceptance or new role.

## Bounded unchanged-failure answer

Only when the issued caller task requests [unchanged Engineering failure resolution](../gamedev-pipeline/references/execution-contract.md#resolve-an-unchanged-failed-attempt), provide the requested condition-bound source evidence, clarification/counterexample or actual missing prerequisite. Credit existing tests and permitted composed proof first. This answer is not a native Review verdict and resolves no findings; write only its exact authorized packet.
