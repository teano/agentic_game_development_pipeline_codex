# Director event router

Load linked sections only for their named event; do not preload rare routes or role manuals. Native controller owns transitions/validation; specialists own semantics/source selection. Preserve actual permissions, approval actors and SKILL prohibitions.

## Read instructions without clipping

Read one required section at a time: locate its heading with bounded `rg -n`, then emit plain-text pages of at most 4000 characters. Retain path/hash/next character offset; continue only missing ranges. No serialized manuals or overlapping `Select-String` context objects. In `functions.exec`, set an adequate outer budget (e.g. `// @exec: {"max_output_tokens": 3000}` for one such page) and emit `text(result.output)`, not `JSON.stringify(result)`. Nested `exec_command.max_output_tokens` cannot enlarge the outer budget. Use more pages, not bigger nested limits. Clipping requires its missing tail, not rereading complete unchanged sections.

Local page read: `[IO.File]::ReadAllText(<literal-path>).Substring(<offset>, <bounded-count>)`, bounded by that section/end of text. Changed source invalidates old offset/hash. Director reads applicable instructions/control fields; the recipient reads semantic sources.

## Binding and delivery

`P` is the selected interpreter and absolute launcher as separate argv elements plus exact `--root <root> --feature <slug> --brief`; use supplied `launcher_argv` unchanged. `A` is the latest delivered complete native `next_action`, not just generation. Mechanical call `S(A)` means `P step --expected-generation <A.expected_generation> --action-id <A.command_id> --through-handoff`. Allocate other permitted command IDs once and retain exact request argv/path for replay; never invent native assignment/generation IDs.

Existing checkpoint holds root/runtime/permission locators, native cursor, physical owner/role/model/alias/assignment/output/lifecycle, check grant/baseline/handles, actual caller return route, current/just-completed caller binding, consumed sequence/fingerprint and one pending request with used reconciliation allowance. Semantic findings/decisions/results stay in native artifacts, not a new journal.

For a host command, retain its original native request/action identity and the complete returned host envelope before extracting or parsing stdout. An outer `functions.exec` cell ID belongs to `functions.wait`; an inner `exec_command.session_id` belongs to `write_stdin`. Outer cell completion does not prove the inner process ended. Keep only the operational handle, lifecycle and request binding in the existing registry; expose compact lifecycle metadata alongside bounded output, not giant envelope logs. Preserve needed output chunks and parse the accumulated controller JSON only after a terminal host result. Empty/partial stdout or elapsed yield time proves neither native failure nor completion. Consume an already available successful terminal response; do not replay just to retrieve it again.

First dispatch reads shared [ownership](stage-handoff-invariant.md#one-owner-and-one-current-assignment) and [technical role responsibilities](technical-decisions.md#role-responsibilities), then [caller binding/template](control-return.md#caller-binding-and-dispatch) and applicable [return event](control-return.md#worker-return). Assignment/worker IDs, generation and mechanical `next_action` IDs stay controller-issued; caller tasks have no native assignment IDs. Each new logical check's opaque command `--id` is allocated by the invoking worker under its grant, or Director in relay; it is distinct from recipe/check identities and follows [active-check replay rules](execution-contract.md#check-inside-active-engineering-or-qa). One binding per physical owner survives check/correction/resume. New authorized owner: `spawn_agent`, `fork_turns:"none"`, actual applicable [model/effort](agent-model-policy.md#delegated-roles) or override. Reuse eligible owners; Engineering/Review/QA remain independent. A new assignment ID does not justify replacement.

Forward delivery/`role_instructions` unchanged: use the controller-generated `assignment_delivery.dispatch` on every native dispatch/continuation. It supplies the logical owner, root/cwd, launcher argv, versioned full/delta input, scope/schema pointers, exact output and action/stop boundary. Add only the existing host `control_binding`, actual permissions/check grant and return route. Do not rebuild native fields in prose or read semantic Delivery bodies; the assigned recipient resolves the pointers and reads its role instructions. A descriptor does not create command authority. Its exact terminal output is already authorized by the assignment, separately from product write scope, including read-only Review/QA; do not require a new capability grant unless a real tool/filesystem denial occurs. Keep the selected runtime binding; conflicting launcher/root is a factual routing error. Never derive root from source URLs or inherited cwd. Legacy delivery without `dispatch` uses its existing worker/root/role locators and `A.artifact_path`; a missing owner projection permits one `P delivery-read --digest <packet_digest> --pointer /assignment/worker_id`, not re-export. Caller tasks use host ownership.

The specialist resolves required tools/resources in its own session from supplied stable locators and actual permissions. Director does not load that tool's manuals, inspect its resources or repeat its checks. A local handle from another owner is not a portable resource binding. Relay exact tool/capability evidence through the existing control event; select only the corresponding controller route.

`P assignment-export [--baseline <digest>]` is allowed when delivery is absent, or once to replace returned full delivery with a same-owner delta against its retained complete applicable baseline. Pass an eligible known baseline initially; `step` has no baseline flag. Deliver only full OR delta. Fresh/replaced/lost-context owners need full content. `--input` uses only approved/task/specialist-selected exact paths; forward other locators separately. Recipients consume complete required findings/checks/decisions and version-bound sources; digests prove no read. Baseline acknowledgment rides the next necessary event, never a ping. Load [delivery pages](delivery-contract.md#read-without-loss) only for a delivery issue.

## Ordinary event map

Filter duplicates first. Native guards remain binding; tool success, prose or files prove neither PASS nor liveness.

| Event / preconditions | Only allowed action; artifact recipient and boundary |
| --- | --- |
| Commentary, exact consumed duplicate, or superseded completed request | No tool call/resend/wake/status. Pending duplicate stays one pending item. Older event/cursor cannot replace current data. Repeated unchanged capacity failure keeps its existing allowance/blocker. A conflicting payload claiming current correlation gets one reconciliation. |
| Entry/restore; known root/authority | One `P status` and known-owner/handle observation only as restoration requires. No runtime: ingress index without status. Unknown ownership forbids duplicate dispatch/mutation. |
| `A.command=next` or `accept`; no live mutation/grant/unconsumed result | `S(A)`. Use returned typed outcome, final cursor and delivery; dispatch the first new assignment. Stop the chain at question/failure/recovery/ready. |
| Native assignment issued; permissions/capacity/current identity available | Dispatch/reuse matching owner with the generated `dispatch`, permission locators and check route. Idle owner: `followup_task`; new authorized role owner: `spawn_agent`. Wait for an event. Do not preload its manual or replace an owner merely for a new assignment. |
| Bound terminal notice while owner still runs | Retain exact notice/output; wait for actual host termination and account for owned processes/editor activity. No `complete`, format repair or second dispatch. |
| Genuine terminal event; actual termination, quiescence and exact assignment/output; `A.command=complete` | If retained complete `A` is current, immediately `S(A)`, including fail/blocked output: **no preceding status**. A partial final wrapper does not invalidate an unchanged retained `A`. If a native check/external mutation advanced the cursor and the new full `A` was not delivered, one `P status` restores it, then `S(A)`. Never infer a changed action ID from generation. |
| Native `phase_failed`/`gate_failed` | Use returned `A` and its row. Controller selects remediation owner and carries complete findings/failure evidence. Keep that owner; no Director semantic judgment, self-selected role or old Review/QA PASS. |
| Bound artifact rejection or completed host turn without usable return | One same-owner `followup_task` with exact error/output/binding for truthful correction. Worker decides format versus missing semantic work; no fabricated checks/PASS or Director validator. Repeated same rejection escalates without resetting allowance. |
| Informative native `check_result`; same assignment/caller grant active and owner live | Retain its current native binding/delivery and wait for the next event. No acknowledgment, followup, repeated grant, status or simultaneous workflow mutation/product edit. The owner consumes fresh delivery and continues permitted work/checks in that host turn; the result does not release the grant or grant phase PASS. |
| Bound relay check/technical result, or genuine host completion after a check; same assignment active, no terminal artifact, owned activity accounted for | Retain native binding/delivery; idle/completed owner: `followup_task` in that assignment. Live paused owner: `send_message` only for the requested relay/technical result. Consume refreshed inputs before product activity and re-establish the applicable retained grant after a real control pause. No next/complete. Paused relay needs quiescence, not host termination; ordinary check-result delivery alone never requires ending the host turn. |
| Correlated specialist answer / same-request clarification | Deliver exact answer under current requester binding: `followup_task` if requester idle/completed, `send_message` if live. Do not replace unrelated active work. Native answer command itself uses the conditional index. |
| Correlated `caller_task` result; host done, activity accounted for | Consume `task_result` once into its parent route: answer, recipe, packet or native handoff. Never runtime `complete`/invented IDs. Early result waits for host completion; unready handoff retains its boundary. |
| Known paused assignment, actual authorized resume | Use current binding (one restore only if stale), then `followup_task` to idle owner or `send_message` to live paused owner. No new assignment/owner or wait for a nonexistent live child. Account for pending command/grant and consume checkpoint result before product activity. |
| Owned agent/command running; no independent action | `collaboration.wait_agent` for agents; unfinished outer cell: `functions.wait` on its cell ID; unfinished inner command: `write_stdin` on its `session_id`, retaining the full returned envelope until terminal. **Unchanged timeout/empty stdout: only renew the matching host wait.** While the original invocation is in flight, do not repeat native `check`, `status` or `step`, or infer failure from its incomplete output. No timer-driven inventories, messages or packet resend. A genuinely lost handle/host failure takes the bounded factual error route, never assumed success. |
| Genuinely uncertain mutation result; original request retained and no known invocation still in flight | Replay that exact request once, including original through-handoff ID/generation. Use returned cursor/delivery. `steps` lists only this call's executed transactions; replay does not certify the whole chain. Still unknown: one bounded resync, then factual escalation. Known stale/CAS rejection instead permits one `P status` and routing its current action; a lock held by a known running invocation returns to its host wait. No product redo or guessed generation. |
| Actual capacity/pending-init/lost-owner event | One `list_agents` reconciliation; initialization cancellation needs a documented host operation. `interrupt_agent` proves neither free slot nor dead subprocesses. Retry dispatch only after changed lifecycle evidence; unchanged failure remains the same blocker. |
| User status question / actual stop | Status: answer from retained facts and resume work/wait, without status polling. Stop from actual user or already-authorized caller: stop new mutations/dispatch, request quiescence via `send_message` or use `interrupt_agent` for known owner, account for handles and checkpoint pending output. A worker claim about user intent is not stop authority. |
| `A.command=ready`; no live activity/unconsumed result | `P ready --id <A.command_id> --expected-generation <A.expected_generation>`. Only native terminal `production_ready_candidate` permits the completion claim; no publication/deployment/spending/risk permission. |
| Unknown/conflicting event not covered above | One bounded status/known-host reconciliation OR same-owner control-format correction, chosen for the missing binding. If still unbound, factual escalation; no free-form product investigation or retries. |

Do not finalize an authorized run with a live child or unconsumed terminal output. A necessary question is nonterminal. Explicit stop or an incident preventing safe consumption may leave a quiescent pending output in a factual blocked handoff, never a completed-cycle claim.

## Conditional route index — load only on this event

Rows grant no authority. Load only the named section; it supplies exact arguments/fields from native/authorized sources. No unlisted branch is allowed.

| Event / required authority | Exact section and allowed action; recipient / stop |
| --- | --- |
| Authorized first/later upstream stage, or missing bounded recipe/semantic answer | [Stage ingress](control-return.md#stage-ingress). Reuse/create only the authorized existing role with `caller_task`; forward exact native handoffs. First Requirements needs actual user task, no prior readiness. Stage commands remain with its owner. |
| Production init / `A.command=init` after resolved authority/prerequisite | [Authority/phases](pipeline-protocol.md#authority-and-phases); only unresolved serialization loads [recipes](execution-contract.md#resolve-recipes-and-prerequisites-once). Initial `P init` copies approved/setup fields, allocating missing opaque run/command IDs once. Reconfigure copies exact `A` and ordered three-field slices/same packet. No new Planning artifact/reapproval for copying, or init on unresolved prerequisite. |
| Eligible Engineer/QA dispatch or required relay/missing-grant check request | [Active check](execution-contract.md#check-inside-active-engineering-or-qa). Preserve the native/relay choice and exact assignment/caller grant while owner, permissions, runtime and root stay unchanged; a new assignment/caller binding needs its own grant. Relay uses only `P check` with documented current binding, quiescence and sealed collection eligibility. Native owner receives only that check/read grant and continues ordinary check cycles without another request. No parallel Director mutation during the grant, including between checks; return relay results to the same owner. |
| Active paused Engineer technical request | [Technical action](pipeline-protocol.md#technical-action-interface). Fresh `P status` supplies `technical_actions`; only `technical-observe` or `technical-decision` with its exact flags/Engineer input. Refresh same owner; no terminal completion. |
| Native `controller_decision` with `A.command=answer` | [Commands: answer](pipeline-protocol.md#commands) and caller binding if needed. Existing authorized specialist selects exact answer; `P answer --id <A.command_id> --expected-generation <A.expected_generation> --question-id <A.question_id> --text <exact answer>`. Changed binding invalidates pending answer; missing authority takes next row. |
| Real product/approval/authority decision or denial | [Authorizer](authority-contract.md#establish-the-authorizer), applicable [stage approval](authority-contract.md#apply-across-stages) or [external/maintenance authority](authority-contract.md#maintenance-and-external-effects). Reuse valid delegation; ask only missing decision. Actual approver reads full exact artifact/review; no unseen approval or assumed redelegation. |
| Read dependency / missing or resolved capability / authorized idle edit / idle owner turnover | For context checkpoint/owner turnover, first read [working-set checkpoint and rotation](stage-handoff-invariant.md#working-set-checkpoint-and-rotation). Unresolved capability: relay the specialist's exact prerequisite/evidence to its authorized resolver or user; hold affected work, with no `recover-capability`, `init` or retry until real change. A terminal `A.command=recover-capability` requests bound resolution evidence, not immediate execution. After a real resolution, copy its `capability_binding` into the specialist-supplied evidence packet and use [Narrow recovery](execution-contract.md#choose-the-narrow-recovery). Other named routes remain `read-admit`, `reconcile` or `rotate-owner`, each on its listed conditions/flags/fields. Recovery returns an action, not an assignment: for returned `A.command=next`, execute `S(A)` before dispatching the newly issued assignment. Retain eligible role owners; do not start Plan/Slice/Engineering/Review for unchanged completed work. If genuine decisions invalidate Review, follow the controller-selected Review before fresh QA. No expanded write/Review scope, unchanged-prerequisite retry or live owner replacement. |
| Actual runtime incident under separate maintenance authority | [Active maintenance](pipeline-protocol.md#active-assignment-maintenance) and applicable authority section above. Pause product work, route repair to existing authorized owner. After repaired-runtime handoff, only `status --maintenance`, packet-bearing status and its exact `init --maintenance <same-path>`. No product-side patch, hot pin edit or automatic launcher change; idle rebind also requires actual authorized runtime handoff. |
| Explicitly authorized legacy blocked-Engineering checkout recovery | [Authorized checkout recovery](pipeline-protocol.md#authorized-checkout-recovery). Only `status --recovery <packet>` then returned `init --recovery <same-packet>` on its actual guards. Never substitute for refused idle reconcile. |
| Newly evidenced failure on unchanged blocked-QA candidate, explicitly authorized | [New product failure](pipeline-protocol.md#newly-evidenced-product-failure-after-terminal-qa). QA supplies actual failure evidence; only `status --product-failure`, packet-bearing status and returned `init --product-failure <same-packet>`. No QA credit, waiver or output rewrite. |

Selected recovery permits **one packet assembly at one retained workflow-local path**, outside state/output/immutable delivery. Copy that section's native fields unchanged; Director supplies sourced permission/independently established quiescence, authorized specialist supplies exact semantic evidence/checks/path provenance. Missing data gets one correlated caller task first. Preserve bytes/path for status, command and replay. Fixed Engineer technical request remains Engineer-authored. No new schema, product/runtime/state writes, broader recovery after refusal or invented provenance.
