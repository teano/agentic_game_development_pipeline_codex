# Review, QA, documentation closure, and recovery

Read this reference only before convergence, Final Review, recovery, runtime QA, derived documentation, or readiness.

## Convergence and Final Review

For convergence, activate the single controller-required read-only Review assignment. Its completion requires an exact reviewer capsule and component-credit manifest; register all supported candidates, then route only the frozen controller-derived remediation batch. Do not add another reviewer merely to repeat already credited scope.

Full convergence accounting is per slice and append-only. The initial whole-candidate cycle credits every covered slice once. Local remediation uses one targeted closure receipt. A second full cycle requires an actual architecture, lifecycle, ownership, public-contract, expanded shared-touchpoint, or broad/high-risk trigger; a third cycle on the same lineage is forbidden.

After clean convergence, obtain the single controller-required Final Review receipt. The same logical independent non-writer ID may produce convergence and Final Review receipts sequentially, but every phase starts in a fresh no-history session after Director boundary validation and receives a new exact capsule. Final Review receives predecessor credit manifests, never predecessor human conclusions. Product rework returns one combined batch to an origin/integration Engineer lease followed by controller-owned coverage finalization and targeted or full revalidation as state requires.

Every convergence/full/targeted completion uses the current command's required capsule and credit manifest. Recovery verification also requires both; no review path relies on an unbounded inherited context.

Allow at most two Review-remediation cycles on one candidate lineage. After the second failed cycle, do not start another reviewer wave or reset counters: use the controller-required fresh Engineer transfer or record the exact manual/user policy hold and minimum resume action.

## Non-product recovery

Support/evidence remediation uses one bounded `recovery_remediator` capsule and exclusive lease, not a product Engineer role. `recovery-remediation-complete` requires the exact frozen non-product finding set, machine checks, a `--semantic-report` file using the shared schema-1 semantic write packet, and a current finalized feature coverage aggregate.

The recovery coverage aggregate must validate on current product/support/evidence identities and preserve continuity with the prior finalized feature aggregate; it cannot silently add identity scope. Product identity drift exits recovery. A recovery Review validates the changed surface, finalized coverage, preserved full-Review credits, exact reviewer capsule, and recovery credit manifest. The existing independent verification worker may perform it when the controller accepts the identity and exact capsule.

A required derived-support contract defect is a `support` finding with exact approved support-path evidence. The controller derives `remediation_required=true` even though product `blocking=false`, and routes it through support recovery. Generic `resolve-finding` cannot close it.

## Exact QA

Before QA activation, record a complete exact-revision capability probe covering only approved prerequisites cited by registered manual identities in exact finalized coverage. This is a subset of the full preflight set when non-manual plan capabilities exist. A ready probe has no external/test blocking status. A blocked probe records every unavailable category and minimum resume action.

Activate QA with exact reviewed identities, finalized manual catalog, capsule, probe, and immutable evidence locations. Preserve the accepted verifier ID when the controller permits, but start QA in a fresh no-history session; do not retain the Review conversation or create another logical verifier merely for role freshness. QA receives Review credit manifests, not human Review conclusions, and returns every registered manual identity exactly once. Executed rows require immutable evidence path/SHA; deferred rows are unexecuted external/test gates; product-blocked rows are unexecuted, non-deferred, and bound to exact findings.

Every failed identity binds to a current QA product finding through `coverage_identity_ids`. Mandatory failure requires an open blocking finding. Optional failure may coexist with aggregate pass only through an accepted nonblocking Minor exact-revision finding. Mixed external gates preserve every category; the controller derives one deterministic overall status and requires `pending-identity` to equal the deferred set exactly.

`qa-complete` writes the immutable run and a current `qa_updated` coverage aggregate. `FAIL_PRODUCT` routes automatically to product remediation. External/test gates resume QA after their exact minimum action and preserve prior engineering/Review credit where identities remain exact.

## Derived documentation and readiness

After QA pass, activate derived Documentation Finisher only when required support outputs have an actual delta; otherwise record exact plan/policy `not_required`. Documentation completion supplies separate semantic write and statement-source-map packets. Derived source-map rows may cite only exact active decisions, the closed QA manual-execution envelope, validated Review credit manifests, and controller handoffs present by path/SHA in the capsule. Generic QA/probe/Review reports are audit-only. Normative rows may cite approved requirements/specification, active decisions, or an unchanged public-contract path from the active lease's pre-write snapshot. No changed semantic-packet path may cite itself or another changed path. Product/evidence/normative drift exits the lane.

A documentation-closure Review validates every changed support statement against controller-recognized sources, unchanged QA product/evidence identities, and current support revision. The same independent verification worker may provide this receipt under a new exact capsule. It grants only support closure credit.

Before `ready`, read `severity-and-readiness.md`, resolve or receipt-accept every Minor finding at its exact revision/reason, verify no remediation-required finding or gate remains, and validate the terminal schema-2 handoff. `ready` declares only a production-ready candidate.
