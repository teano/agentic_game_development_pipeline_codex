# Review, QA, documentation closure, and recovery

Read this reference only before convergence, Final Review, recovery, runtime QA, derived documentation, or readiness.

## Convergence and Final Review

For convergence, the Director activates two or three fresh read-only Review stages concurrently with distinct lenses and no shared conclusions. Every completion requires an exact reviewer capsule and component-credit manifest. Wait for the complete wave, register all supported candidates, and route only the frozen controller-derived remediation batch.

Full convergence accounting is per slice and append-only. The initial whole-candidate wave credits every covered slice once; the hard maximum is two full waves. Local remediation uses one targeted closure reviewer. A second full wave requires an actual architecture, lifecycle, ownership, public-contract, expanded shared-touchpoint, or broad/high-risk trigger.

After clean convergence, activate exactly two fresh full Review stages on one immutable identity set with complementary lenses. Each reuses valid exact component credits and freshly inspects composition/new boundaries. Product rework returns one combined batch to an origin/integration Engineer lease followed by coverage finalization and targeted or full revalidation as controller state requires.

Every convergence/full/targeted completion uses the current command's required capsule and credit manifest. Recovery verification also requires both; no review path relies on an unbounded inherited context.

## Non-product recovery

Support/evidence remediation uses one bounded `recovery_remediator` capsule and exclusive lease, not a product Engineer role. `recovery-remediation-complete` requires the exact frozen non-product finding set, machine checks, a `--semantic-report` file using the shared schema-1 semantic write packet, and a current finalized feature coverage aggregate.

The recovery coverage aggregate must validate on current product/support/evidence identities and preserve continuity with the prior finalized feature aggregate; it cannot silently add identity scope. Product identity drift exits recovery. A fresh recovery Review validates the changed surface, finalized coverage, preserved full-Review credits, exact reviewer capsule, and recovery credit manifest.

A required derived-support contract defect is a `support` finding with exact approved support-path evidence. The controller derives `remediation_required=true` even though product `blocking=false`, and routes it through support recovery. Generic `resolve-finding` cannot close it.

## Exact QA

Before QA activation, record a complete exact-revision capability probe covering the same closed capability set approved at preflight. A ready probe has no external/test blocking status. A blocked probe records every unavailable category and minimum resume action.

Activate one fresh QA stage with exact reviewed identities, finalized manual catalog, capsule, probe, and immutable evidence locations. QA returns every registered manual identity exactly once. Executed rows require immutable evidence path/SHA; deferred rows are unexecuted external/test gates; product-blocked rows are unexecuted, non-deferred, and bound to exact findings.

Every failed identity binds to a current QA product finding through `coverage_identity_ids`. Mandatory failure requires an open blocking finding. Optional failure may coexist with aggregate pass only through an accepted nonblocking Minor exact-revision finding. Mixed external gates preserve every category; the controller derives one deterministic overall status and requires `pending-identity` to equal the deferred set exactly.

`qa-complete` writes the immutable run and a current `qa_updated` coverage aggregate. `FAIL_PRODUCT` routes automatically to product remediation. External/test gates resume QA after their exact minimum action and preserve prior engineering/Review credit where identities remain exact.

## Derived documentation and readiness

After QA pass, activate derived Documentation Finisher for exact required support outputs or record exact plan/policy `not_required`. Documentation completion supplies separate semantic write and statement-source-map packets. A source-map row may cite only a controller-recorded immutable SHA: approved PRD/specification, active decision ledger, preserved Review/QA/probe/handoff evidence, or an unchanged public-contract path from the active lease's pre-write checkout snapshot. No changed semantic-packet path may cite itself or another changed path. Product/evidence/normative drift exits the lane.

A fresh documentation-closure Review validates every changed support statement against controller-recognized sources, unchanged QA product/evidence identities, and current support revision. It grants only support closure credit.

Before `ready`, read `severity-and-readiness.md`, resolve or receipt-accept every Minor finding at its exact revision/reason, verify no remediation-required finding or gate remains, and validate the terminal schema-2 handoff. `ready` declares only a production-ready candidate.
